# 機能要件定義書

| 項目 | 内容 |
|---|---|
| 文書名 | 機能要件定義書 |
| 対象システム | 読書記録 |
| 版 | 1.0 |
| 作成日 | 2026年10月26日 |
| 作成者 | nsb |
| 関連資料 | ドキュメント一覧、要件定義書、用語定義書、機能要件、非機能要件、画面見取り図、画面設計書、操作手順書、ER図、ユースケース、データベース設計、技術スタック、API仕様書、`frontend/index.html` |
| 目的 | 利用者ができることを、きっかけ、処理、事後条件まで定義する |

この資料は、機能の定義です。資料の入口は「ドキュメント一覧」です。番号の正は「要件定義書」の「作ること」です。確認用の一覧は「機能要件」です。言葉の意味は「用語定義書」に従います。機能以外の約束は「非機能要件」です。

新しい操作は、この資料では足しません。作らないことの正は「要件定義書」の「作らないこと」です。

画面は1枚です。ファイルは `frontend/index.html` です。利用者は、登録した人です。本は、その人の SQLite の行に残します。ページを閉じても、その行は残ります。ログインしないと、一覧は出ません。

## 1. 読み方

| 項目 | 意味 |
|---|---|
| 番号 | 要件定義書の A-1 から A-3 と、B-1 から B-4。この資料では振り直さない |
| きっかけ | 利用者が行う操作、またはページを開くこと |
| 事前条件 | 処理の前に成り立っていること |
| 処理 | システムが行うこと |
| 事後条件 | 処理のあとで成り立つこと |
| 例外 | その番号だけでは足りないときの扱い |

## 2. A-1 登録する

| 項目 | 内容 |
|---|---|
| 番号 | A-1 |
| できること | 登録する |
| 対応する流れ | UC-2 |
| きっかけ | 名前とパスワードを入れ、登録を押す |
| 事前条件 | ログインしていない |
| 処理 | `POST /api/register` を送る。SQLite の `users` に1行作り、セッションを発行する |
| 事後条件 | ログインしている。名前が表示される。自分の本の一覧が出る。登録直後は0件 |
| 例外 | 名前が約束に合わない、パスワードが8文字未満、または同じ名前があるときは、登録しない。一覧は出ない |
| 画面 | `frontend/index.html` |

## 3. A-2 ログインする

| 項目 | 内容 |
|---|---|
| 番号 | A-2 |
| できること | ログインする |
| 対応する流れ | UC-3 |
| きっかけ | 名前とパスワードを入れ、ログインを押す。または、残っているセッションでページを開く |
| 事前条件 | その名前が登録されている。ページを開き直すときは、有効なセッションがある |
| 処理 | `POST /api/login` を送る。一致したらセッションを発行する。開き直すときは `GET /api/me` と `GET /api/books` を送る |
| 事後条件 | その人の本だけが一覧に出る。他のアカウントの行は見えない |
| 例外 | 一致しないときは、ログインしない。一覧は出ない |
| 画面 | `frontend/index.html` |

## 4. A-3 ログアウトする

| 項目 | 内容 |
|---|---|
| 番号 | A-3 |
| できること | ログアウトする |
| 対応する流れ | UC-4 |
| きっかけ | ログアウトを押す |
| 事前条件 | ログインしている |
| 処理 | `POST /api/logout` を送る。セッションの行と Cookie を消す |
| 事後条件 | ログイン欄に戻る。本の一覧は出ない。その人の本は SQLite に残る |
| 例外 | ログインしていないときにログアウトしても、失敗にはしない |
| 画面 | `frontend/index.html` |

## 5. B-1 本を追加する

| 項目 | 内容 |
|---|---|
| 番号 | B-1 |
| できること | 本を追加する |
| 対応する流れ | UC-5 |
| きっかけ | 題名、著者、状態、メモを入れ、追加を押す |
| 事前条件 | ログインしている |
| 処理 | `POST /api/books` を送る。題名と著者の前後の空白は除く。`books` に1行作る |
| 事後条件 | その本が一覧の先頭に出る。追加欄は空に戻る |
| 例外 | 題名または著者が空、状態が3つのどれでもない、メモが400文字を超えるときは、追加しない |
| 画面 | `frontend/index.html` |

## 6. B-2 一覧を見る

| 項目 | 内容 |
|---|---|
| 番号 | B-2 |
| できること | 一覧を見る |
| 対応する流れ | UC-1、UC-6 |
| きっかけ | ログインする、本を追加する、本を直す、本を削除する、ページを開き直す |
| 事前条件 | ログインしている |
| 処理 | `GET /api/books` を送る。自分の行だけを、`id` の大きい順に出す |
| 事後条件 | 自分の本が新しい順に見える。0件のときは「まだ本がありません。」 |
| 例外 | ログインしていないときは、一覧を出さず 401 を返す |
| 画面 | `frontend/index.html` |

## 7. B-3 本を直す

| 項目 | 内容 |
|---|---|
| 番号 | B-3 |
| できること | 本を直す |
| 対応する流れ | UC-7 |
| きっかけ | 一覧の題名、著者、状態、メモを変え、保存を押す |
| 事前条件 | ログインしている。その本が自分の行である |
| 処理 | `PUT /api/books/{id}` を送る |
| 事後条件 | 一覧がその値になる。ページを開き直しても残る |
| 例外 | 値が約束に合わないときは更新しない。自分の本でない id は 404 で、行は変えない |
| 画面 | `frontend/index.html` |

## 8. B-4 本を削除する

| 項目 | 内容 |
|---|---|
| 番号 | B-4 |
| できること | 本を削除する |
| 対応する流れ | UC-8 |
| きっかけ | 削除を押し、確認する |
| 事前条件 | ログインしている。その本が自分の行である |
| 処理 | 確認のあと `DELETE /api/books/{id}` を送る |
| 事後条件 | その本は一覧から消える。SQLite からも消える |
| 例外 | 確認を取り消すと、何もしない。自分の本でない id は 404 で、行は残る |
| 画面 | `frontend/index.html` |

## 9. 作らないこと

要件定義書で作らないとしたものは、この定義に入れません。

- 他の人の本を見ること
- 表紙画像、貸出、評価の点数
- 全世界への公開
- PostgreSQL と RDS
- この版での AWS の起動
